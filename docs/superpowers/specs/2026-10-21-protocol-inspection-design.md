# 七项协议巡检设计

用户已批准实施上一轮建议；开发前节点为 1cf6eae。本设计细化已批准范围，不改变既有巡检计划与告警生命周期。

## 目标与边界

保留旧服务的基础端口/HTTP检查，明确标注基础检查。每项服务可启用深度检查配置：服务器 SSH 认证与挂载点磁盘阈值、MySQL/PostgreSQL SELECT 1、Redis AUTH/PING、Kafka 集群元数据、RabbitMQ AMQP 连接、RocketMQ NameServer 路由信息、MinIO S3 指定桶访问、HTTP 请求和响应断言。生产收发消息及对象读写不在基础验收范围。Linux/POSIX 服务器为本轮服务器范围。

## 采集架构

本机 HertzBeat 模板已读取：Linux/JDBC/Redis/RabbitMQ/RocketMQ存在，Kafka模板为JMX而非客户端协议，MinIO模板不存在。为让本地检查、手动执行和外部告警保持相同语义，使用统一 Java 协议探测器；HertzBeat 继续作为采集调度、告警及可用性引擎，website Monitor 通过平台的只读协议探测接口触发一次真实探测。已同步的深度服务沿用现有机制跳过本地周期检查；未同步服务保留本地兜底。外部实例必须配置能访问平台的内部地址。

内部探测接口位于 /internal/inspection/{assetId}，使用独立的每服务派生 Basic 凭据，只返回本次是否通过，不输出详情。仅启用计划的当前服务有效；每次有执行资源的有效请求执行一次真实协议探测，失败或配置/归属在执行中改变返回503；错误凭据返回401。HTTP 200只代表本次全部检查通过，不读取旧缓存。现有可用性告警规则由website DOWN触发，连续失败次数明确为HertzBeat对探测链路的失败采样次数（包含真实协议失败及忙碌/过载/超时等采集基础设施故障），不把手动测试计入告警次数。内部请求凭据绑定assetId和配置revision，配置修改后旧请求拒绝，等待Monitor补偿同步。

## 配置、安全与结果

独立 ops_inspection_profile 表按assetId唯一保存配置、加密密文与最近结果。AES-GCM，主密钥由 OPS_INSPECTION_MASTER_KEY 提供（Base64 32字节）；未配置密钥时可以启动旧功能，但禁止保存深度检查密文。读接口不回传密码、私钥、passphrase、access/secret key、HTTP敏感请求头及请求体。空缺secret字段表示保留，显式空串删除。错误消息使用固定错误分类，不传递协议库可能包含凭据的原始消息。

支持超时（1至10秒）、数据库名、Redis TLS、HTTP方法/状态码/响应包含断言、SSH已知主机公钥校验、磁盘挂载点白名单与排除项、容量使用率阈值（1至100）。SSH必须核对主机密钥，不自动信任未知主机。所有结果包含检查名称、通过状态、可读详情、耗时；磁盘逐挂载点展示实际值和阈值。类型变化在已有启用配置时拒绝，要求先停用；保存配置或修改连接地址后旧结果立即不可用。

## 集成与验收

配置API、前端表单、手动测试与计划执行使用同一探测入口。配置保存使用服务级事务锁；探测使用有界并发（最多16项）和每服务互斥，单次服务总预算30秒、单操作1至10秒；忙碌/过载返回503并显示原因，计入探测链路故障告警；这是刻意的基础设施可用性语义，不声称每次DOWN都代表目标协议失败。HertzBeat website timeout设置为45000毫秒，高于30秒总预算并留出提交与传输余量；低于总预算的计划周期可能重叠并产生链路忙碌告警，表单提示周期应大于检查总耗时。网络探测在数据库事务外，结果单服务短事务及时提交。执行快照绑定配置revision、服务type/endpoint、planId、bindingId及plan desiredVersion，保存前重新校验归属与启用状态；旧执行结果不得进入当前配置。手动测试也遵守互斥和版本校验，只更新最近明细，不计入HB告警采样。删除服务清理配置。新增深度配置时既有Monitor下次配置同步转website真实协议探测接口；停用配置回到旧模式。

验收包括：密文和密钥缺失、保留/删除凭据、接口不泄密、错误配置、未知主机密钥、真实HTTP断言、真实Redis AUTH/PING、数据库查询、SSH磁盘解析/阈值/排除目录、MQ和S3适配器正常/失败、并发互斥、停启/转移后旧结果拒绝、慢服务不阻塞其他服务、未授权访问、计划同步/启停/删除、历史基础检查回归。可用本机受控容器补真实协议验证，不修改业务实例数据。自动测试和真实验证的范围必须分别报告，不把模拟测试当作全部真实验收。
